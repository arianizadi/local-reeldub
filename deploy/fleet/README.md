# Private render workers

One coordinator serves the customer API, receives authenticated job claims, and owns the encrypted media cache. The downloader uses its own VPN. Each GPU requests work from the private coordinator when it has a rendering slot. The iPhone only needs the public API hostname.

1. Provision PostgreSQL metadata with the existing ReelDub schema. Mount encrypted storage for the media database, credentials and temporary files in a dedicated control guest. Install the server requirements in a virtual environment, a compatible MongoDB server binary, nginx and OpenSSH. The service installer defaults to `/opt/reeldub` and `/srv/reeldub-private`.
2. Install the [isolated intake guest](../proxmox-intake/README.md). Configure the coordinator with its HTTPS address and client certificate. Keep the VPN profile and CA signing keys private.
3. Generate credentials for each trusted GPU with `enroll-node.sh NODE SLOTS` on the coordinator. Set `REELDUB_SECRET_DIR` and `REELDUB_FLEET_IP`. Securely deliver the resulting node directory to the intended worker. It contains a client key, certificate, CA certificate and bearer token. Restrict the coordinator port to the private LAN or VPN. Remove a node from the registry to revoke its application access. Renew certificates before they expire.
4. Provision `api.env`, `operator.env`, `fleet.env`, `intake.env`, MongoDB credentials and certificates, and an origin key restricted to the gateway's loopback port. The fleet service uses a metadata role with claim/update access and access to source records and GridFS. The node receives only its own worker credentials. Run `control-services.sh` with `REELDUB_FLEET_IP`, `REELDUB_PUBLIC_HOST` and `REELDUB_ORIGIN_SSH`. The script writes systemd units. Start the media, API, fleet, fleet-proxy, ingress and origin units after validating the data migration. Enable the loopback operator only where needed.
5. Install the Studio pipeline, the server Python requirements, Landlock ABI 6+ with landrun, and the distribution’s Python seccomp bindings on the GPU. Set `REELDUB_LANDRUN` if the binary is outside its standard native installation path. Keep service keys outside the code and model directories. The offline engine invokes the pinned translator over standard I/O. Seccomp denies creation of network sockets and connections to host services. The trusted transfer process uses TLS. Use the private coordinator IP in the URL and the certificate SAN, or configure a matching hosts-file entry. The restricted worker disables ordinary UDP DNS. Supply `REELDUB_WORKER_CONFIG`, `REELDUB_FLEET_URL`, `REELDUB_FLEET_NODE`, `REELDUB_SERVICE_PYTHON`, `REELDUB_GPU_PIPELINE_SLOTS` and optionally `REELDUB_DEVICE_ID`. Run `worker-service.sh`. Drain any direct worker sharing that GPU, then enable the printed instances. Use one node identity per independently scheduled GPU and the same lock directory for all slots on a card. Start new hardware at one slot.
6. Verify a real request, completed playback, admin GPU sample, rejection without worker credentials, and service recovery on a guest reboot. A lost lease can be retried up to the existing attempt limit. Never point serving API or GPU instances at two divergent media databases after a cutover. Reconcile new artifacts before rolling a live media store back.

The coordinator holds assigned inputs and outputs outside Neon. It serves input only to the current worker lease, streams bounded uploads and fences publication on the same lease. Progress and work claims reuse the existing queues and job quotas. Idle claims use the local media store to check for work; PostgreSQL supplies durable queue order and recovery. Network transfer, prep, model loading and the ratio of long to short Reels affect the best slot count.

## Recovery and renewal

Nodes send a health pulse every 15 seconds. The coordinator uses the private media database for health. After a node goes silent it stops new assignments, marks the node offline and requeues its interrupted work ahead of ordinary submissions. Success requires a current lease. The worker retries temporary transfers before giving up its slot. Three interrupted attempts release the original reservation. A source that cannot be dubbed can still fail independently of infrastructure health.

The worker checks access to pinned local weights, available scratch space and a real CUDA allocation. After an outage it must pass preflight again. A single node can resume work when healthy. Adding a second independent GPU host supplies failover capacity during an outage.

Monitor certificate expiry with `openssl x509 -checkend 2592000 -noout -in client.pem`. Generate a CSR on the worker with its existing private key and subject `/CN=NODE`. Run `renew-cert.sh node NODE worker.csr > client.next.pem` on the management machine holding the CA. Install the verified certificate beside the existing worker key and restart idle slots. For the coordinator listener, `renew-cert.sh server` reuses the private listener key. Validate the private nginx config before reloading it. Keep signing keys on encrypted administration storage.

## Control guest service identities

Run `bash control-services.sh prepare` as root with `REELDUB_FLEET_IP`, `REELDUB_PUBLIC_HOST` and the restricted `REELDUB_ORIGIN_SSH` destination. Set `REELDUB_EXPECTED_PRIVATE_SOURCE` to the mounted storage device or ZFS dataset reported by `findmnt -no SOURCE -M /srv/reeldub-private`. On the storage host, verify the dataset encryption and key status first. The installer checks physical credential files and certificate chains, records the expected volume identity and tests the combined systemd sandbox on this guest.

The API, operator and fleet service have individual UIDs with shared GID 1915 for the metadata DSN and private intake identity. Separate identities own the media database, private worker listener, public ingress and origin tunnel. Each has a mode-0700 temporary directory on the encrypted volume. Systemd loads root-only environment files. Verify the permission matrix using `python3 verify-control-isolation.py`.

For an existing database, wait for queued and running jobs to drain, stop `reeldub-media` cleanly, run `bash control-services.sh media-ownership`, and start the media service. Start or restart the operator, fleet service, API, private listener, public ingress and origin. Run `bash control-services.sh enable` for automatic boot and `python3 verify-control-isolation.py --running` to verify the actual process UIDs. Verify local readiness, public HTTPS, authenticated private worker access and the operator relay before retiring the previous installation.
